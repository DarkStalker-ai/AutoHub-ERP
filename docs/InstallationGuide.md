# Інструкція з інсталяції та налагодження AutoHub ERP

**Версія документа:** 1.0  
**Версія програмного забезпечення:** 0.2.0-beta

## 1. Призначення документа

Документ описує підготовку середовища, налаштування PostgreSQL, конфігурацію та запуск AutoHub ERP. Наведені нижче команди призначені насамперед для локального навчального розгортання з .NET 9 SDK. Для виробничого сервера спосіб публікації та хостингу потрібно адаптувати до його операційної системи й інфраструктури.

## 2. Склад програмних компонентів

| Компонент | Призначення | Джерело |
|---|---|---|
| Опубліковані файли AutoHub.Web | Серверна частина вебзастосунку | Результат `dotnet publish` |
| .NET 9 Runtime | Виконання framework-dependent публікації | Офіційний дистрибутив .NET |
| PostgreSQL Server | Зберігання даних | Офіційний дистрибутив PostgreSQL |
| Конфігурація застосунку | Параметри підключення та поведінки | Налаштовується під час розгортання |
| Браузер | Доступ користувачів до вебінтерфейсу | Встановлений на комп'ютері користувача |

У поточній архітектурі PostgreSQL є окремим серверним компонентом. Файли бази даних не потрібно копіювати до каталогу вебзастосунку або включати до звичайного пакета публікації.

## 3. Вимоги до середовища

Для локального запуску з вихідного коду потрібні:
- .NET 9 SDK;
- PostgreSQL Server;
- Git (якщо отримання виконується через репозиторій);
- веббраузер.

Для запуску framework-dependent публікації потрібен .NET 9 Runtime. На Windows із IIS потрібен сумісний ASP.NET Core Hosting Bundle. Якщо обрати self-contained публікацію, runtime включається до публікації для конкретної цільової платформи.

## 4. Отримання та підготовка проєкту

1. Отримайте вихідний код AutoHub ERP з архіву або репозиторію.
2. Розпакуйте його в робочий каталог.
3. Відкрийте термінал у корені репозиторію.
4. Перейдіть до каталогу `AutoHub`:

```powershell
cd .\AutoHub
```

## 5. Налаштування PostgreSQL

1. Встановіть і запустіть PostgreSQL Server.
2. Створіть базу даних, наприклад `autohub_erp`.
3. Підготуйте окремого користувача БД із правами, необхідними для роботи застосунку та застосування міграцій.
4. Збережіть рядок підключення в User Secrets для локального середовища розробки:

```powershell
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Host=localhost;Port=5432;Database=autohub_erp;Username=<db_user>;Password=<db_password>" --project .\AutoHub.Web\AutoHub.Web.csproj
```

Замініть `<db_user>` і `<db_password>` реальними значеннями. Не додавайте пароль до Git або документації.

## 6. Налаштування початкового адміністратора

Якщо механізм початкової ініціалізації ввімкнений, задайте облікові дані початкового адміністратора через User Secrets:

```powershell
dotnet user-secrets set "BootstrapAdmin:Username" "<admin_username>" --project .\AutoHub.Web\AutoHub.Web.csproj
dotnet user-secrets set "BootstrapAdmin:Password" "<strong_unique_password>" --project .\AutoHub.Web\AutoHub.Web.csproj
```

Використовуйте унікальний пароль. Не використовуйте демонстраційний або загальновідомий пароль у розгорнутій системі.

Перевірте параметр `Database:InitializeOnStartup`. Якщо він має значення `true`, застосунок викликає механізм ініціалізації БД під час запуску. Перед використанням наявної бази даних обов'язково перевірте стан міграцій і резервну копію. Не запускайте міграції повторно на базі з невідомим станом.

## 7. Відновлення залежностей і запуск

У каталозі `AutoHub` виконайте:

```powershell
dotnet restore
dotnet build
dotnet run --project .\AutoHub.Web\AutoHub.Web.csproj
```

Після запуску відкрийте адресу, яку виведе ASP.NET Core у консолі. У стандартному профілі розробки проєкту можуть використовуватися адреси `http://localhost:5164` та `https://localhost:7199`; фактичні адреси визначаються активним профілем запуску.

## 8. Публікація застосунку

Для підготовки Release-публікації виконайте з каталогу `AutoHub`:

```powershell
dotnet publish .\AutoHub.Web\AutoHub.Web.csproj -c Release -o .\publish
```

Каталог `publish` міститиме файли опублікованого застосунку. Не включайте до дистрибутива `appsettings.Development.json`, User Secrets, паролі, локальні журнали, `.git`, `.vs` та проміжні каталоги `bin` і `obj`.

Перед розгортанням перевірте, що конфігурація для цільового середовища передається безпечним способом — наприклад, змінними середовища або захищеним сховищем секретів.

## 9. Розміщення та доступ користувачів

Опублікований застосунок потрібно розмістити на сервері, який має мережевий доступ до PostgreSQL. Користувачі відкривають адресу вебзастосунку у браузері.

Для Windows Server можна розглянути IIS із встановленим ASP.NET Core Hosting Bundle. Для іншого середовища можна використати підтримуваний спосіб запуску ASP.NET Core за reverse proxy або як керованого сервісу.

Не відкривайте порт PostgreSQL у публічну мережу без необхідності. Для віддаленого доступу до вебзастосунку налаштуйте HTTPS.

## 10. Перевірка після встановлення

Після розгортання виконайте перевірки:

1. Переконайтеся, що вебзастосунок запускається без критичних помилок.
2. Перевірте доступність сторінки входу.
3. Увійдіть під початковим адміністратором.
4. Перевірте відкриття розділів автомобілів, марок і клієнтів.
5. Створіть тестовий запис і перевірте його збереження.
6. Перевірте доступ до адміністративного розділу.
7. Створіть тестового користувача з роллю `Manager` і перевірте обмеження доступу.
8. Перевірте журнал аудиту та системні параметри.
9. Відкрийте сторінки Help та About.
10. Переконайтеся, що застосунок доступний через HTTPS у цільовому середовищі.

## 11. Видалення або оновлення

Перед оновленням:
1. Створіть резервну копію бази даних.
2. Збережіть конфігурацію середовища окремо від файлів застосунку.
3. Перевірте сумісність нової версії з поточною схемою БД.
4. Розгорніть нову публікацію.
5. Перевірте запуск і основні функції.

Видалення файлів вебзастосунку не повинно автоматично означати видалення бази даних. Видалення БД виконується окремо та лише після погодження й створення резервної копії.

## 12. Усунення типових проблем

| Проблема | Можлива причина та дія |
|---|---|
| Не вдається підключитися до PostgreSQL | Перевірте, чи запущена служба PostgreSQL, адресу, порт, назву БД і облікові дані |
| Помилка автентифікації PostgreSQL | Перевірте ім'я користувача та пароль у конфігурації |
| Не знайдено .NET Runtime | Встановіть сумісний .NET 9 Runtime або використайте self-contained публікацію |
| Порт вебзастосунку зайнятий | Перевірте процес, що використовує порт, або змініть адресу запуску |
| Помилка під час міграції | Перевірте історію EF Core migrations і фактичну схему БД; не видаляйте таблиці навмання |
| Не працює вхід | Перевірте наявність активного облікового запису та правильність пароля |
| HTTP працює, HTTPS ні | Перевірте сертифікат і налаштування HTTPS у цільовому середовищі |

## 13. Примітка щодо інсталятора

Цей документ описує склад компонентів і процедуру розгортання. Сам по собі він не означає, що інсталятор Inno Setup уже створено. Сценарій `.iss`, пакування опублікованих файлів, перевірки передумов і тестування інсталяційного пакета виконуються окремо в межах завдання 3 лабораторної роботи №6.
